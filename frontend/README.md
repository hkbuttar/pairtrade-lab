# frontend/

Panel app: the third distinct Python dashboard paradigm across this
portfolio's projects (alpha-signal-lab's Streamlit script-rerun model,
bookmaker/execedge's raw Bokeh server with periodic DB-polling callbacks,
and this project's `param.Parameterized` widgets driving recomputation
reactively on change). Panel wraps Bokeh plots directly (`pn.pane.Bokeh`,
see `plots.py`), reusing this portfolio's existing Bokeh plotting fluency
for the actual charts, and runs on Bokeh's server under the hood
(`panel serve`), so widget interactions push updates rather than the
browser polling.

**There is no live paper-trading scheduler in this project** (see root
README Future Work), so "live" in every view here means "recomputed
against the latest cached price data when a widget changes," not a
continuous feed. Every tab says so rather than implying more than it
delivers.

`colors.py` reuses the dataviz skill's validated reference palette
verbatim, the same values bookmaker's `frontend/colors.py` uses: fixed
categorical slots per series identity, reserved status colors for
ACTIVE/HALTED never reused for a series.

`data_access.py` computes (doesn't query) what each view needs straight
from `pairs/`, `signals/`, and `monitor/`, wrapped in `@pn.cache` so
switching tabs or the selected pair doesn't redundantly re-run an
expensive selection or rolling-monitor computation already done this
session.

`plots.py` builds two Bokeh figures: a z-score time series with
entry/exit/stop-loss reference lines, trade-entry markers, and shaded
HALTED regions; and a bar-plus-CI-whisker chart for the Step 9 comparison
metrics.

`app.py` assembles four tabs:
- **Live Monitoring** — status, current z-score, days since last break,
  and rolling p-value for every pair currently surviving FDR-corrected
  selection.
- **Spread & Z-Score** — the full z-score chart above, selectable by pair
  via a reactive widget.
- **Comparisons** — the Step 9 baseline-vs-variant bar charts, loaded from
  a **precomputed, committed snapshot**
  (`backtest/results/comparison_2018-01-01_2025-01-01.json`, generated by
  `backtest/run_comparison.py --output-json ...`) rather than recomputed
  live: a full four-way comparison run takes roughly two minutes, too slow
  for a page load. Re-run the CLI and overwrite the JSON to refresh it.
- **Alert Feed** — every structural break detected for the selected pair,
  with halt/resume dates and duration.

Run with:

```bash
panel serve frontend/app.py --show
```

(The `sys.path` insert at the top of `app.py` is required: `panel serve`
execs the file with only `frontend/` on `sys.path`, not the repo root, the
same issue and fix as bookmaker's `frontend/main.py`.)
